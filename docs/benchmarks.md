# Benchmarks

> 逐周期实测数据：Release 构建、WSL/Linux、同一工具链与镜像布局。每个用例
> 的 `result` = 停机时架构寄存器 x10 的低 8 位，`cycles` 为总周期数。
>
> **本表即行为回归的 golden 数据源**（`data/golden/` 已废弃删除）：根 `test.sh`、
> `RISC-V-Simulator-Template/test.sh`、根目录 `test_M.sh`、
> `RISC-V-Simulator-Template/docs/plru_regress.sh` 均直接读本表 —— `result` → x10、
> `cycles` → clock；路径可用环境变量 `GOLDEN_MD` 覆盖。
> 行为回归（退出码 / x10 / 崩溃检测）由根目录 `test.sh` 执行。

## Constraints

- Main memory latency is fixed at **50 cycles**（取指侧 IMEM 缺失回填与数据侧 DCache
  缺失回填共用该延迟）。
- No L1 cache hit latency：ICache 命中当拍组包、DCache 命中 1 拍自答（store 当场落行）。
- L1 cache：指令缓存 **8 KB**（512×16 B，直接映射）+ 数据缓存 **64 KB**（1024 组×4 路×16 B，
  写回 + 写分配，tree-PLRU）。D$-% 覆盖 load 与 store 的全部访存访问。
- 预测准确率按控制流类型拆分：**cond** = 条件分支（BRU 解析，方向+目标）；
  **jal** = 直接跳转（JAL，ALU 结果总线）；**jalr** = 间接跳转（JALR）；
  **branch** = 三者汇总的整体准确率（与 README 口径一致）。

```bash

# branch: 111/175 correct (63.43%)
```

> 逐列取数口径：`cond-%` / `jal-%` / `jalr-%` / `branch-%` 由**命中分数**换算
> （`correct/total × 100`，最多 4 位小数、去尾零；分母为 0 记 `0`），
> `I$-%` / `D$-%` 直接取对应行的 `hit-rate`（固定 2 位小数）。
> `result` = 停机 x10 低 8 位，`cycles` = 总周期数。


## RV32M A/B（硬件乘除法收益实测）

> 统一双臂 A/B 语料（`data/testcases_rv32im/`）：
> **M 臂** = `-march=rv32im`（乘法 `mul/mulh/...` 与除法 `div/divu/rem/remu` 全部内联为硬件单元，
> 链接行去掉 `libdiv.S`）；**I 臂** = `-march=rv32i` + `libdiv.S`（软例程 `__mulsi3` 负责 `*`、软除法例程负责 `/` 与 `%`）。
> 两臂同 `crt0` / 同链接脚本 / 同 `-O1`（避 `magic.c` 的 `-O2` UB），故 clock 差即**纯 M 扩展（乘+除）收益**；
> **实际运行时间**由 `test_M.sh` 直接执行模拟器二进制、以 `date +%s%N` 测墙钟得到（同一次运行内两臂同口径）。
> `x10` 两臂一致即视为通过；`x10` 另对照主表 `result` 列（课程原镜像口径，自制镜像 layout 不同，仅比 x10）。

### 读法

- **收益与乘/除的动态占比正相关**：`pi`（除法占周期 99%+）提速 **17.58×**（约 1.38 亿 → 784 万周期）；
  `gcd`/`manyarguments`/`lvalue2`/`basicopt1`/`expr` 等除法位于热循环，提速 **1.8–3.2×**；
  `statement_test` 乘法集中（3 条静态 `mul`），提速 **2.04×**。
- **阴性对照**：`naive` 无 `mul`/`div`（静态条数 0/0），M/I 双臂 clock 逐拍相同（183）；`qsort`/`tak`/`magic` 仅 1 条
  `div/rem` 且不在热路径，clock 几乎不动（Δclock ≈ 0）——证明收益完全来自硬件乘/除单元。
- **`magic` 的 Δclock≈0 是真实结果**：其唯一 `div` 位于数据相关循环，硬件 SRT 与软 `libdiv.S` 在该用例的
  实际延迟接近，故收益被其余工作稀释；`pi` 的同类 `div` 因量级巨大才显出 17× 收益。
- **跨臂 brAcc 不可直接比较**：两臂编译出的代码不同，软例程自带大量分支（如 `gcd` 的 M 臂仅 7 次分支、
  I 臂 125 次），准确率差反映**代码差异**而非预测器退化；预测器回归仍以「同一镜像跨模拟器版本」对主表四列为准
  （2026-09-12 复核：18/18 逐列零漂移）。

> 逐用例双臂对拍由根目录 `test_M.sh` 驱动（含实际运行时间列）；本表为其实测落盘，口径与 `test_M.sh` 一致。
