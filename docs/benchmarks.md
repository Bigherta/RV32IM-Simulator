## Constraints

- Main memory latency is fixed at **20 cycles**（取指侧 IMEM 缺失回填与数据侧 DCache
  缺失回填共用该延迟）。
- ICache 命中时序：第 n 拍接受请求并读同步 SRAM，第 n+1 拍若读结果属于队首且 FQ
  可接收，直接旁路交付；已消费的读结果跳过落槽，背压或非队首结果仍落槽保存。
  DCache入队与查询分离；n拍读data/metadata SRAM，n+1拍命中Load返回，允许安全Load
  hit-under-miss。Store按接受顺序实际写data/metadata后完成，四MSHR owner包含在四项总请求信用中。
- L1 cache：指令缓存 **1 KB**（16×64 B，直接映射，`SRAM<16,512,32>`）+ 数据缓存
  **4 KB**（64组×2路×32 B，每way八个`SRAM<64,32,8>`＋`SRAM<64,22>`，独立valid，PLRU、写回＋写分配）。
  D$回填每拍64bit，共4拍；分配时清victim valid，首拍返回Load并准备合并等待者，末拍发布完整行。
  DMEM读写共享16项混合队列，每拍最多一读一写，信用竞争优先写；完成携带原MSHR ID，每项仍20拍。
  D$-%统计实际查询的Load/Store，含已经接受、随后被恢复取消的查询。
- ICache 请求队列保留 4 项；回填写优先于新命中读，端口冲突只反压取指，后端继续推进。
- 核心容量：ROB 16 / PRF 48（`REGISTER_CAP + ROB_CAP`）/ FQ 2 / IQ 2 / LQ 8 / SQ 8；RS 为
  Integer 2 / Multiply 1 / Divide 1 / Branch 2 / Load 2 / StoreAddr 2 / StoreValue 2。
- 队列实际可用 2/2/8/8；LSQ 恢复快照保存完整 epoch 序号，memIndex 仅使用物理槽。
- RAS 深度 16；空栈 pop、满栈 push 保持原状态；预测、提交基线与 ROB 重放均不越界。
- 分支方向预测：Tournament（local/global/selector 各 256×2-bit，8-bit GHR）；目标侧保留
  BTB64 / RAS16（非环形 depth top；archRAS 基线 + ROB 重放）/ condSeen512。
- 预测准确率按控制流类型拆分：**cond** = 条件分支（BRU 解析，方向+目标）；
  **jal** = 直接跳转（JAL，ALU 结果总线）；**jalr** = 间接跳转（JALR）；
  **branch** = 三者汇总的整体准确率（与 README 口径一致）。

### Tournament 面积终态（2026-09-20）

为进一步压低面积，方向侧从 TAGE 改为 Tournament：local/global/selector 各 256×2-bit，
GHR 为 16 bit；目标侧 BTB64、RAS8、SARAS16、condSeen512 保持不变。
按模板 `Register<N>` 实际位宽计数，完整 BPU 状态由 **24,357 bit** 降至
**12,558 bit**，减少 **11,799 bit（48.44%）**。该数字覆盖方向表、目标侧、32 份
checkpoint、ckpt 指针和 boot 位，不包含 host-only 统计计数器。

`taken` 的 BTB 命中门控做了隔离 A/B：A 为 `btbHit && directionTaken`，B 允许方向表在
BTB miss 时直接 taken。18 例主语料 A/B 分别为 **12,237,892 / 12,250,503** cycles，
分支正确率 **93.8367% / 93.6618%**；独立 IPC 六例分别为 **495,871 / 495,830** cycles。
按主语料优先的既定口径采用 A。相对上一活动 TAGE 基线 12,036,972 cycles，Tournament
增加 200,920 拍（**+1.6692%**），加权 IPC 0.562945→**0.553703**，分支正确率
95.7208%→**93.8367%**；18/18 x10 正确且两树逐例 clock 一致。

### 间接目标缓存删除（2026-09-20）

Tournament 落地后，BHT256 与 Target Cache32（及其 `isCall/isIndirect` BTB 元数据）只彼此
服务、没有独立收益：TC 训练/查询只覆盖"真间接"JALR，而全部活动语料（18 例 + IPC 6 例）
里的 JALR 不是返回就是调用，唯一真间接站点是 `towers` 的 `auipc + jalr x0, -924(x6)`，
目标固定（TC 与 BTB last-target 相同）。因此按面积/效率权衡删除该闭环。按模板
`Register<N>` 位宽计再省 **3,232 bit**（BHT 2,048 + TC 1,024 + TargetValid 32 +
BTB `isCall/isIndirect` 128），完整 BPU 状态 **12,558 → 9,326 bit**，相对 TAGE 基线
24,357 bit 为 **−61.71%**；
18 例与 IPC 语料 x10/clock 逐位不变。

### GHR / checkpoint 载体收紧（2026-09-21）

SARAS `times` 先从 32 bit 收紧为 9 bit：RAS 与 AlignQueue 共 24 个载体，省
**552 bit**，完整状态 **9,326 → 8,774 bit**。此前的 9,454 / 8,902 账本遗漏了随
Target Cache 一并删除的 BTB `isCall/isIndirect` 两个 64 项元数据位（128 bit）。

Tournament 的 globalPHT/selector 索引均为 `((PC>>2)^GHR)&255`，故 GHR 的高 8 位从未
被消费；`GHR_WIDTH=8` 及其容量断言将 live GHR 和 32 份 checkpoint 中的 GHR 同步收紧，
省 **8 + 32×8 = 264 bit**。SARAS `alignHead` 只被 snapshot/restore，无推进或消费者，
删除其 live 与 checkpoint 载体再省 **8 + 32×8 = 264 bit**。完整 BPU 状态最终为
**8,774 → 8,246 bit**，相对 TAGE 基线 24,357 bit 为 **−66.15%**；该变换不改变预测索引。

### BTB 字段收紧（2026-09-21）

BTB 索引为 `PC[7:2]`，因 RV32IM 活动镜像无压缩指令，PC 与跳转目标均为 4-byte 对齐。因此每项的
完整 PC 可由 `PC[31:8]` tag 与索引重建，目标低两位恒为零；`valid/conditional/unconditional/return`
四态合并为一个 2-bit `state`（return 同样强制 taken）。模板 `Register` 项由
`{actualPC[31:0], target[31:0], valid, unconditional, isRet}` 的 **67 bit** 收紧为
`{tag[23:0], target[29:0], state[1:0]}` 的 **56 bit**。BTB64 共省 **64×11 = 704 bit**，完整
BPU 状态 **8,246 → 7,542 bit**，相对 TAGE 基线 24,357 bit 为 **−69.04%**；该变换保留全部
预测语义。根树与模板 Release 均为 18/18 x10+cycles 对 golden，模板 `_DEBUG` 全量 18/18
零断言；三者总 clock 均为 **12,237,892**。

取数命令（WSL ELF 构建，逐用例）：

```bash
VERBOSE=branch,clock,icache,dcache <bin> < data/testcases/<case>.data >/dev/null
# clock: 177
# ipc: 0.232955 retired=41 cycles=176
# branch: 1/7 correct (14.29%)
# branch-type: cond=1/5(20.00%) jal=0/1(0.00%) jalr=0/1(0.00%)
# icache: hits=61 misses=19 total=80 hit-rate=76.25%
# dcache: hits=1 misses=1 total=2 hit-rate=50.00%
```

> 逐列取数口径：`cond-%` / `jal-%` / `jalr-%` / `branch-%` 由**命中分数**换算
> （`correct/total × 100`，最多 4 位小数、去尾零；分母为 0 记 `0`），
> `I$-%` / `D$-%` 直接取对应行的 `hit-rate`（固定 2 位小数）。
> `result` = 停机 x10 低 8 位；`cycles` = 端到端总周期；`ipc-cycles` = HALT 提交周期；
> `retired` = 排除 HALT 标记后的实际 ROB 退休数；`IPC = retired / ipc-cycles`（保留 6 位小数）。

### 读法

- **收益与乘/除的动态占比正相关**：`pi`（除法占周期 99%+）提速 **17.601×**（约 1.38 亿 → 782 万周期）；
  `gcd`/`manyarguments`/`lvalue2`/`basicopt1`/`expr` 等除法位于热循环，提速 **1.87–3.44×**；
  `statement_test` 乘法集中（3 条静态 `mul`），提速 **2.241×**。
- **阴性对照**：`naive` 无 `mul`/`div`（静态条数 0/0），M/I 双臂 clock 逐拍相同（93）；`qsort`/`tak`/`magic` 仅 1 条
  `div/rem` 且不在热路径，clock 几乎不动（Δclock ≈ 0）——证明收益完全来自硬件乘/除单元。
- **`magic` 的 Δclock≈0 是真实结果**：其唯一 `div` 位于数据相关循环，硬件 SRT 与软 `libdiv.S` 在该用例的
  实际延迟接近，故收益被其余工作稀释；`pi` 的同类 `div` 因量级巨大才显出 17× 收益。
- **跨臂 brAcc 不可直接比较**：两臂编译出的代码不同，软例程自带大量分支（如 `gcd` 的 M 臂仅 7 次分支、
  I 臂 125 次），准确率差反映**代码差异**而非预测器退化；预测器回归仍以「同一镜像跨模拟器版本」对主表四列为准
  （2026-09-18 复核：18/18 x10 全对）。
