# 访存：LQ/SQ、转发与退出

## Load 与 Store 的生命周期

LQ 和 SQ 各有 8 项。按序分配时预留队列槽；Load 和 Store 地址共用 AGU，Store 数据单独交付。地址和返回数据必须匹配原请求身份，错路 Load 的迟到响应不得写回。

- **Load**：先尝试 SQ 转发，不能转发时通过冲突检查，再请求 D$。LQ 内部保存原始数据，写回时按宽度和符号扩展。合格的缓存返回可在到达拍竞争 Load 独立写回口；实际广播只标记一次，ROB 退休才释放 LQ 槽。
- **Store**：地址和数据齐备才通知 ROB 就绪。已提交或本拍实际退休的 SQ 队首可向访存系统发送，D$ 接受后才释放 SQ 槽。分支恢复不会取消已提交 Store。

## 转发与仲裁

- 从较老或已提交 Store 中选择最年轻的重叠来源。该来源须覆盖全部字节、数据已就绪，且比候选中的未知地址 Store 更年轻；不拼接多个 Store 的数据。
- 未转发的 Load 遇到地址未知或字节重叠的更老未提交 Store 时，不进入 D$。Store 地址事件不直接向 Load 送数据；合格的 Store 数据事件可通知等待的 Load。
- SQ 队首 Store 通常优先。满足 `SQ ≤ 4`、无在途 Load owner、普通 RAM 且字节不重叠等条件时，允许安全 Load 先行一次，随后恢复 Store 优先。

## 课程退出

程序向 `0x80000000` 写入一个完整 32 位结果。该 Store 退休时冻结核心及 IPC 统计，并计入退休数；已提交 Store 和在途事务继续推进。退出写不分配缓存行，对应 AXI B 握手后输出结果并结束，不扫描全部脏行。

课程周期为 `init + core + drain`。软件日志 `timing.total` 只含 `core + drain`，日志中的 IPC 以 `core` 为分母。
